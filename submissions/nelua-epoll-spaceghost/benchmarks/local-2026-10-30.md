# Local full-seed development measurements — 2026-10-30

These are short mixed-workload checks on one shared development host, not official challenge scores. The load generator shares CPU with PostgreSQL and the application. The reference full seed passed its stock fingerprints: 500,000 articles, about 5 million favorites, about 2.5 million comments, about 2 million follows, and 100,000 users; loaded database size 3,560 MB.

The runs use a five-second ramp, twenty-second measurement, three-second tail, and `-think-scale 0.1`. This accelerates both think time and session turnover; virtual-user counts must not be compared with the official unscaled five-minute holds. No affinity or kernel tuning was used. PostgreSQL 18.0 used the local test cluster configuration, rather than the dedicated benchmark box configuration.

The first native run preceded the generic-plan and bcrypt scheduling fixes. The default remains four read workers: six reduced queue latency here but increased total host CPU enough to trigger the load-generator limited flag. Every case still met the aggregate latency/error thresholds; flagged cases establish no server ceiling. The unmodified C comparator remains faster in this short local comparison, so no win or ranking is claimed.

The C comparator is `c-epoll-umitaltintas` from repository commit `d373e0dd994f4683a94c783627078431561d07f6`, built unchanged with its original `-O2 -march=native` flags and the same libpq/OpenSSL/libxcrypt libraries. Its published official score is unrelated to these accelerated local virtual-user counts.
